# 示例应用 需求工作区（虚构示例）

> ⚠️ **这是 prd-builder 的格式示例，不是真实需求。**
> 「示例应用」「意见反馈」及其中所有字段、状态、规则、数字均为虚构，只用来演示文件怎么摆、怎么写，**不构成任何业务规则，禁止照搬到真实需求里**。

本目录按 prd-builder 规范组织：功能台账 + 版本目录 + 页面目录。

## 目录结构

```text
readme.md                    # 本文件：结构说明
feature/
  index.md                   # 功能清单
  意见反馈/README.md         # 功能定义；规格只放链接
  意见反馈/versions.md       # 跨版本记录
versions/
  v1.0/
    index.md                 # 版本总纲（总控维护）：版本级决策、术语表、页面清单与分工……
    WORKLOG.md               # 总控过程日志：需求盘点、任务卡、跨页影响裁决；不进 Git
    01-提交反馈/             # 定义「反馈」实体与状态机（主管页面）
    02-反馈处理/             # 引用 01 的状态机，不重复定义
      WORKLOG.md             # 本页过程日志：跨页影响上报、同步回执；不进 Git
```

## 看点

- 这是**项目模式**示例（两页、两个会话并行）。轻量 / 标准模式只交一份 `<需求名>/PRD.md`，不需要这些目录。
- 版本目录统一放在 `versions/` 下。
- 两个角色：总控出总纲（`versions/v1.0/index.md`）和任务卡（`versions/v1.0/WORKLOG.md`「任务卡」），页面会话按卡细化。
- PRD 用 SKILL.md「PRD 必含内容」的骨架：目标与范围 → 场景与流程 → 功能与规则 → 验收标准（每条注明验证哪条 R）。
- WORKLOG 只记增量：快照每轮覆盖、变更记录每轮一行、已关闭项进「归档」。
- 跨页影响走一圈：02 在自己 WORKLOG 上报 X-1 → 总控裁决成版本级决策 D-00-02、下发「待同步」→ 02 改完写同步回执。
- 页面可以引用版本级决策：02 的 PRD 写「遵守 D-00-02」，脚本会去 index 核对。
- 术语表：「工单、投诉单」是「反馈」的禁用别名，页面里写了就会被 validate 报错。
- 编号带页号：01 页是 `R-01-001`，02 页是 `R-02-001`。
- 共用状态机「谁主管谁定义」：反馈状态机定义在 `01-提交反馈`，`02-反馈处理` 通过 `refs` 引用并写「见 R-01-003」。
- 版本 `index.md` 末尾的「交付与修订记录」代替 CHANGELOG。
