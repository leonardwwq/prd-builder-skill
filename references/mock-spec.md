# HTML mock 规范

mock 是给人看的：让产品、设计、技术在读代码之前，先看见这次改动长什么样。什么时候画见 SKILL.md「产物选择」；非界面需求（纯规则、纯接口）不画。

## PRD 锚点

在 PRD 对应区块末尾独占一行（格式别改，build_review / validate 靠它定位）：

```
<!-- mock: mocks/01-默认态.html | 说明文字 -->
```

有 mock 就生成 review.html：`node <技能目录>/scripts/build_review.mjs <PRD 所在目录>`。

## 铁律

1. **单文件、零外部依赖**。不引 CDN、字体文件、外链图片，样式全写在 `<style>` 里。内网断网、别人电脑没装字体、整个文件夹打包发出去，都得能打开。
2. **只画本次动到的页面和状态**。不画整站导航，不画已存在且没改的页面。
3. **假数据贴近真实**。格式、长度、量级参考项目真实资料（字段长度上限、金额量级、列表条数）；不用 `Lorem ipsum`、`测试1`、`张三 123` 这种看不出约束的数据。涉及真实个人信息时做脱敏。
4. **改动点必须标出来**。评审的人没空对比旧原型。
5. **一个文件一个状态**。同一页面的默认态 / 空态 / 异常态拆成不同文件。

## 文件命名

放在页面目录的 `mocks/` 下，按 PRD 里出现的顺序编号：

```
mocks/01-默认态.html
mocks/02-空态.html
mocks/03-校验失败.html
```

一个页面里有多个区块且状态较多时，可按区块分子目录（编号与 PRD 的区块编号 `3.N` 对齐）：

```
mocks/3.1-列表/01-默认态.html
mocks/3.2-详情弹窗/01-默认态.html
```

## 页面骨架

复制 `templates/mock-skeleton.html`，包含：

- 顶部说明条：写「页面 · 状态 · 本示意仅表达改动点，非最终视觉」及关联编号
- 改动点标注：红框 `.changed` / 蓝框 `.modified` + 橙色角标（①②③…），底部图例逐条解释
- 画布：PC 默认 `width:1440px`；移动端 `width:375px` + 手机外框；同一改动涉及两端就并排两块
- 底栏：mock 文件路径与版本，截图时自带上下文

## 标注约定

| 标记 | 含义 | 用法 |
| --- | --- | --- |
| 红虚线框 + 角标 | 本次新增 | `<div class="changed" data-note="1">` |
| 蓝虚线框 + 角标 | 本次修改 | `<div class="modified" data-note="2">` |
| 灰删除线 | 本次移除 | `<span class="removed">旧字段</span>` |

图例逐条写，如 `① 新增「<字段名>」字段，必填，最多 100 字（R-NN-001）`。
只标改动，别把整页框成红的——满屏重点等于没重点。

## 状态覆盖参考

- 默认态：必有
- 空态：列表类必有
- 校验失败 / 错误态：有表单必有
- 超长文本 / 长列表：字段有长度上限时给一个
- 权限不足 / 禁用态：有角色差异时给一个
