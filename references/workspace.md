# 需求工作区：文件职责与更新时机

一个工作区对应一个产品，分三层：

- **功能台账** `feature/`：按功能看，跨版本追踪「这个功能经历了哪些版本」。
- **版本目录** `versions/<版本号>/`：按版本看，「这一版要做什么、拆成哪些页面、走到哪一步」。
- **页面目录** `versions/<版本号>/NN-<页面名>/`：交付物本体，每页一套 PRD + spec + review + mocks。

功能与版本是多对多关系，用链接互连，不用目录嵌套表达。

## 文件职责与写权限

| 文件 | 写什么 | 不写什么 | 谁写 | 进 Git |
| --- | --- | --- | --- | --- |
| `readme.md`（工作区根） | 目录结构、各文件作用、使用方式；「本工作区约定」（项目特有的命名、术语、流程习惯）；可选的产品级术语表 | 具体需求正文 | 总控 | 是 |
| `feature/index.md` | 功能清单：功能名、一句话简介、最新涉及版本、跳转链接 | 功能细节 | 总控 | 是 |
| `feature/<功能名>/README.md` | 功能是什么、边界、当前状态；当前规格所在页面的链接 | 状态机、字段表等规格内容（只链接，不抄） | 总控 | 是 |
| `feature/<功能名>/versions.md` | 该功能每个版本改了什么、涉及哪些页面（只追加） | 版本内修订细节 | 总控 | 是 |
| `versions/<版本号>/index.md` | **版本总纲**：目标与范围、版本级决策、术语表、页面清单与分工、跨页流程、共用定义指路、交付与修订记录 | 页面需求正文 | 总控 | 是 |
| `versions/<版本号>/WORKLOG.md` | 总控过程：工作状态、资料索引、需求项盘点、任务卡、版本级开放问题、跨页影响裁决、流程草图、下一步、变更记录 | 正式规格、页面细节 | 总控 | **否** |
| `versions/<版本号>/NN-<页面名>/WORKLOG.md` | 本页过程：进度、事实与缺口、待定决策、开放问题、跨页影响上报、同步回执、变更记录 | 正式规格 | 该页 | **否** |
| `versions/<版本号>/NN-<页面名>/PRD.md` | 该页面 / 流程包的权威需求 | 别的页面的定义（引用编号即可） | 该页 | 是 |
| `versions/<版本号>/NN-<页面名>/spec.yaml` | 机器可读规格，本页编号在这里定义 | 同上 | 该页 | 是 |
| `versions/<版本号>/NN-<页面名>/review.html` | 脚本生成的人读版 | 手写内容 | 该页（脚本） | 是 |
| `versions/<版本号>/NN-<页面名>/mocks/` | 本页改动涉及的页面状态示意 | 未改动页面 | 该页 | 是 |

例外：交付登记时总控改各页 `meta.status`；用户明确指定时总控代改某页（见 SKILL.md「写权限」）。

**WORKLOG.md 不进 Git。**工作区在 Git 仓库内时，用 `git check-ignore -v <路径>` 检查；未被忽略时告诉用户，建议在 `.gitignore` 加一行 `WORKLOG.md`（匹配所有层级），用户同意后再改。`validate.mjs` 会同时检查版本与页面的 WORKLOG。

## 版本 index.md（总纲）的固定区块

1. **版本目标与范围**：为什么做、做什么、不做什么。
2. **版本级决策**：`编号 | 结论 | 依据 / 确认人 | 影响页面`，编号 `D-00-xx`。只放已确认的；页面可引用。
3. **术语表**：`标准叫法 | 含义 | 禁用别名`。禁用别名用「、」分隔，脚本据此扫描页面。
4. **页面清单与分工**：页号 | 页面 / 流程包 | 简介 | 主管实体 | 依赖 | 批次 | 负责人 | 状态 | 链接。流程包写明合并理由；版本需求清单的每一项都要能在这里找到归属。
5. **跨页流程总览**：步骤 | 操作者 | 动作 | 所在页面。
6. **共用定义指路**：实体 / 状态机 / 规则 | 定义在哪页（含编号或 spec 位置）| 被哪些页引用。
7. **存量数据处理汇总**（版本级唯一一份，总控维护）：存量对象与范围 | 处理方式 | 用户可见变化 | 提供方 | 执行方 | 核对方 | 时机 | 怎么验证 | 定义在 | 状态。没有写「本版不涉及存量数据」。
8. **交付与修订记录**（只追加）：日期 | 类型（交付 / 修订）| 对象 | 内容 | 涉及页面。没交付前这张表为空。

骨架见 `templates/version-index.md`。区块标题里的关键字（版本级决策、术语、页面清单、共用定义、存量数据、交付与修订）别改，脚本靠它定位。

## 什么时候更新什么

| 时机 | 谁 | 要动的文件 |
| --- | --- | --- |
| 开始一个新版本 | 总控 | 在 `versions/` 下建版本目录、`WORKLOG.md`、`index.md` 草稿 |
| 总纲确认、分工 | 总控 | `index.md`；版本 `WORKLOG.md` 任务卡 |
| 页面开工 / 每轮结束 / 暂停 | 该页 | 本页 `WORKLOG.md` |
| 页面确认后写正式规格 | 该页 | 页面目录四件套 |
| 用户在总控会话说「打包」 | 总控 | 汇总各页「未完成与依赖」→ validate → `commit_paths.mjs` 一次提交；版本 `WORKLOG.md` 记提交号。页面会话从不提交 |
| 页面标「可登记」 | 总控 | `index.md` 页面清单与共用定义指路；首次出现的功能建 `feature/<功能名>/`，`feature/index.md` 加一行 |
| 页面上报跨页影响 | 总控 | 裁决后改 `index.md`（如涉及）、受影响页任务卡「待同步」、版本 `WORKLOG.md` 裁决表 |
| 交付 | 总控 | 各页 `meta.status: 已交付` 并重跑脚本；`index.md` 交付记录；相关 `feature/<功能名>/versions.md`；`feature/index.md` 最新版本 |
| 交付后在本版修订 | 该页改内容，总控记录 | 页面文件、重跑脚本；`index.md` 追加修订记录 |
| 用户要求开新版本 | 总控 | 新建版本目录，只放本版改动的页面；旧版不动 |

## 版本 WORKLOG 必备区块（总控）

骨架见 `templates/WORKLOG.md`：

1. **目标与约定**：需求来源、用户约定、最终交付物。
2. **工作状态**：当前阶段（收料 / 版本级梳理 / 待确认总纲 / 分工中 / 收口 / 交付）、已完成、进行中、是否暂停。
3. **资料索引**：原型、文档、代码路径；注明已查范围与读不了的材料。
4. **需求项盘点**：需求项 | 来源 | 归属页面 | 备注。
5. **任务卡**：每页一张（字段见 [`role-lead.md`](role-lead.md) L3）。
6. **版本级开放问题**：`Q-00-xx` | 问题 | 证据 | 影响页面 | 需谁回答 | 阻塞。
7. **跨页影响裁决**：来源页 | 事项 | 结论 | 受影响页 | 同步状态。
8. **流程草图**：跨页链路；区分「材料明示」与「推测待定」。
9. **下一步**：1–5 步，具体到文件或页面。
10. **变更记录**：日期 + 本轮补充 / 修正；推翻旧结论时写明依据。

## 页面 WORKLOG 必备区块

骨架见 `templates/page-WORKLOG.md`：

1. **任务卡指针**：任务卡位置、本页按哪个「卡片更新日期」开工。
2. **工作状态**：阶段（收料 / 杠 / 待确认 / 产出 / 收尾）、是否「可登记」。
3. **事实与缺口**。
4. **待定决策**：`D-NN-xx`，确认并落 spec 后只留指向。
5. **开放问题**：`Q-NN-xx`。
6. **跨页影响**（上报给总控）。
7. **同步回执**（总控「待同步」项的完成记录）。
8. **总控代改记录**（有才写）。
9. **未完成与依赖**：没写完的部分、依赖谁的什么、被谁等着、是否阻塞；每轮收尾必更，没有写「无」。
10. **下一步 / 变更记录**。

## 拆分与合并

- 默认一页一个目录。弹窗、抽屉、详情页等依附于主页面的，随主页面放。
- 几个页面共享同一状态机且必须一起评审 / 一起开发时，可合成流程包目录，在版本 index 写明合并理由。
- 版本需求清单里的每一项，都要在版本 index 的页面清单里找得到归属，不许漏。
- 单页 `spec.yaml` 超过约 800 行时，考虑拆页或拆流程包，而不是在页内再嵌套目录。拆页是总控的事。
