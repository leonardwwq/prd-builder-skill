# 角色：需求总控

总控对**整个版本**负责：帮用户把这一版要做什么定下来，拆成页面，分给页面会话，并把跨页的事收口。总控**不细化页面**。

只在项目模式使用；工作区、写权限、编号、术语、存量数据、版本、WORKLOG、Git 规则以 [`workspace.md`](workspace.md) 为准，本文件只写总控的流程。版本只有一页、单会话时通常不需要项目模式（见 SKILL.md「先定模式」）；用户仍要求时，总纲可以很薄（范围 + 页面清单 + 一张任务卡），再在同一会话切成页面角色，切换时说一声。

## 细化到哪一步就停

总控的产出要能回答每个页面的三件事，答到了就停：

1. **做什么**：这页覆盖哪些需求项、哪些原型页，主管哪些实体。
2. **不做什么**：明确不归这页的东西（归哪页、或本版不做）。
3. **跟谁有关系**：依赖谁的定义、谁依赖它、跨页流程里它负责哪一步。

字段表、交互细节、校验规则、异常分支、验收用例都是页面的事，总控不问也不写。遇到用户主动聊页面细节，记进那页任务卡的「交给本页的问题 / 已知输入」，不在总控这里展开。

## 流程

### L0 · 收料与盘点

- 读全部版本级材料：版本需求清单、原型、需求池、旧版本 index、相关 feature 台账。读不了的格式让用户导出，不说「看过了」。
- 列**需求项盘点表**（版本 WORKLOG）：每一项需求 → 来源 → 初步归属页面 → 是否有现成说明。一项都不许漏，最后每项都要能在 index 页面清单找到归属，或标明「本版不做」。
- 输出两栏：已掌握的事实（带来源）/ 缺口。

### L1 · 版本级杠

只问会影响**全局**的问题，维度见 [`grill-playbook.md`](grill-playbook.md)「总控用」一节。典型：

- 本版目标、成功判定、硬截止。
- 范围边界：哪些明确不做、哪些沿用现状。
- 页面怎么划：哪些合成流程包、理由是什么。
- 共用实体：有哪些、各归哪页主管。
- 跨页主流程：几条主链，每一步落在哪页。
- 统一叫法：同一个东西各处叫法不一的，定一个。
- 存量数据：本版哪些改动会动到老数据、怎么处理、谁来协作；总控维护版本级唯一一份「存量数据处理汇总」，页面在规则里写细节并上报。
- 版本级通用口径：多页都要遵守的规则（时区、币种与精度、通用权限模型、通用审批 / 通知框架之类），只定「是什么、归哪页定义」，不展开细则。

规矩同页面角色：每轮只问当下卡全局的，判断题给选项、推荐项放第一个；产品取舍问用户，工程事实找技术负责人；用户说「你定」只代定产品取舍并标「由我代定」。不阻塞全局的细节，直接下放到页面任务卡。

### L2 · 出总纲（硬门槛：用户确认后再分工）

总纲就是版本 `index.md`：骨架 `templates/version-index.md`，固定区块与列见 [`workspace.md`](workspace.md) 第 8 节。存量数据处理汇总是版本级唯一一份；没有写「本版不涉及」。

把总纲交给用户核对。**范围、页面划分、共用定义归属没拿到明确确认，不发任务卡。**

### L3 · 发任务卡

每个页面一张，写在版本 `WORKLOG.md`「任务卡」一节（骨架在 `templates/WORKLOG.md`）。一张卡包含：

| 项 | 写什么 |
| --- | --- |
| 覆盖范围 | 需求项编号、原型页 / 材料位置 |
| 不做 | 明确不归本页的内容及其去向 |
| 主管实体 | 本页必须定义的实体 / 状态机 / 规则 |
| 引用 | 本页要引用的外部编号或定义页（已存在的写编号，未存在的写「待 NN 定义」） |
| 已定的版本级决策 | 与本页相关的 `D-00-xx` |
| 交给本页的问题 | 总控不展开、由本页去杠的点 |
| 已知输入 | 用户已经说过的页面细节（原话或要点 + 来源），防止页面会话重复问 |
| 依赖与批次 | 等谁先定什么；能否和谁并行 |
| 完成标准 | 默认：本页 validate 无错误 + 用户核对过基本流程 + 本页 WORKLOG 标「可登记」 |
| 待同步 | 总控下发的、需要本页改的事项（见 L4）；无则写「无」 |
| 卡片更新日期 | 每次改卡都更新，页面会话据此判断要不要重读 |

排批次的原则：主管共用实体的页面先做；只引用别人的页面，等被引用的定义出了草稿再做细节；彼此不依赖的可以并行。

告诉用户怎么开页面会话，例如：「新开会话，说：用 prd-builder，做 v<版本> 的 NN-<页面名>」。

### L4 · 收口：跨页影响裁决与同步

页面会话不改别人的文件，发现跨页的事写在自己 WORKLOG「跨页影响」里。总控每轮（或用户说「收一下」时）：

1. 扫所有页面 WORKLOG 的「跨页影响」，状态为「待总控」的逐条处理。
2. 能直接定的（比如明显该归某页主管）直接定；涉及产品取舍的问用户。
3. 定了以后：
   - 版本级的 → 写进 index（版本级决策 / 术语表 / 共用定义指路 / 流程总览）。
   - 要别的页改的 → 在受影响页面的任务卡「待同步」里加一条（写清改什么、依据哪个编号），更新卡片日期。
   - 在版本 WORKLOG「跨页影响裁决」表登记：来源页、事项、结论、受影响页、同步状态。
4. 页面上报的存量数据处理，收进 index「存量数据处理汇总」，新增或变化的项单独告诉用户。
5. 扫页面 WORKLOG 的「同步回执」，对应「待同步」项改成已完成；扫「未完成与依赖」，把页面之间的等待关系更新到对应任务卡的「依赖与批次 / 待同步」。
6. 跑版本级 `node <技能目录>/scripts/validate.mjs <版本目录>`，把跨页引用断掉、禁用别名残留之类的错误，按归属分发给对应页面的「待同步」。

改名（术语变更）固定走：记 `D-00-xx` → 术语表旧名进「禁用别名」→ 受影响页「待同步」→ 页面改完后 validate 不再报别名。

### L5 · 打包、登记与交付

打包、交付汇报里，凡涉及存量数据的单独列给用户（对象、方式、执行方、时机、是否已准备好）。

**打包（只有总控做，且只在用户说「打包 / 提交 / 推送」时）**：按 [`workspace.md`](workspace.md) 第 10 节：确认页面会话已停手 → 汇总各页 WORKLOG「未完成与依赖」列给用户 → 跑版本级 validate → 用户确认后用 `commit_paths.mjs` 一次交齐 → 用户要推再推。打包后在版本 WORKLOG 变更记录写一行（提交号、包含哪些页、仍未完成的依赖）。

- 页面 WORKLOG 标「可登记」后，总控更新 index 页面清单（状态、链接）、共用定义指路，必要时建 / 更新 `feature/<功能名>/`。
- 用户说交付时：确认相关页面会话都已停手 → 各页 `meta.status` 改「已交付」并重跑 build + validate → index「交付与修订记录」追加 → 各相关 `feature/<功能名>/versions.md` 追加、`feature/index.md` 更新最新版本。
- 汇报：本版定了哪些版本级决策、哪些页已交付、还有哪些开放问题（版本级 + 各页非阻塞）、技术拿到手第一步该看什么。

## 总控自己的 WORKLOG

版本 `WORKLOG.md` 只有总控写，骨架 `templates/WORKLOG.md`，记法（快照覆盖、只追加一行变更、续作只读快照与未关闭项）见 [`workspace.md`](workspace.md) 第 9 节。已确认的版本级结论在 index，WORKLOG 只留指向，不复写。

## 什么时候总控可以碰页面文件

只有用户明确指定时（见 [`workspace.md`](workspace.md) 第 2 节的例外）。其余情况一律通过「待同步」让页面会话去改。
