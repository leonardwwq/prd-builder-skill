# <产品名> 需求工作区

本目录按 prd-builder 规范组织：功能台账 + 版本目录 + 页面目录；分「需求总控」和「页面 PRD」两个角色干活。

## 目录结构

```text
readme.md                  # 本文件：结构说明、本工作区约定（总控维护）
feature/
  index.md                 # 功能清单、简介、最新涉及版本、跳转（总控维护）
  <功能名>/README.md       # 功能定义；当前规格只放链接
  <功能名>/versions.md     # 该功能跨版本记录，只追加
versions/                  # 需求版本，一版一个目录
  <版本号>/
    index.md               # 版本总纲：范围、版本级决策、术语、页面清单与分工、流程、共用定义指路、交付记录（总控维护）
    WORKLOG.md             # 总控过程日志与任务卡，不进 Git
    NN-<页面名>/
      WORKLOG.md           # 本页过程日志，不进 Git
      PRD.md               # 权威需求文本
      spec.yaml            # 机器可读规格
      review.html          # 人读版，脚本生成，勿手改
      mocks/               # HTML 示意
```

## 怎么用

- 看某个版本做什么、拆成哪些页、谁先谁后：打开 `versions/<版本号>/index.md`。
- 看某个功能经历了哪些版本：打开 `feature/index.md` → 对应功能。
- 评审某一页：打开该页面目录的 `review.html`。
- 开发 / 交给 AI 实现：以页面目录的 `PRD.md` + `spec.yaml` 为准，版本级决策与术语见版本 `index.md`。
- 提交：页面会话不提交；所有改动由总控在用户说「打包」时统一提交。
- 开会话：「用 prd-builder，当 <版本号> 的总控」或「用 prd-builder，做 <版本号> 的 NN-<页面名>」。

## 编号

`<类型>-<页号>-<序号>`，类型：R 规则、G 验收、T 任务、D 决策、Q 开放问题。例：`R-01-003`。`00` 号是版本级（`D-00-xx` 在版本 index，`Q-00-xx` 在版本 WORKLOG）。
